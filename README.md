# Product City · 产品之城

用 AI，把 idea 具现化。一条沿河街道、五栋产品建筑和记录早期尝试的旧城区。52 个 Hi3D 源模型（5 栋建筑 + 46 种街道装饰与居民 + 1 位新主角），通过 Blender MCP 修复几何与法线，并为旅行创作者和 9 位居民绑定骨骼动画。当前场景使用 40 种道具、5 栋建筑、一栋旧城区复用建筑和主角，共 103 个实例；6 个不适合摆放的模型保留在资源库。

线上站点：https://mycity.up.railway.app

模型入口：https://mycity-assets.lafreze-city.workers.dev/mycity/ （只提供具体模型文件，不列出目录）

## 本地运行

需要 Node.js 20 或更新版本；前端依赖已经随仓库提供，无须安装运行依赖。

```sh
npm run dev
```

打开 http://127.0.0.1:4173 即进入三维街区。本地页面也使用远程 R2 模型，因此需要联网。

```sh
npm run check
VERIFY_ORIGIN=https://mycity.up.railway.app npm run assets:verify
```

## 托管与空闲成本

- GitHub 保存网站源代码、资源清单、来源记录和部署配置。大模型与嵌入贴图位于 Cloudflare R2，不进入 Git 历史或 Railway 镜像。
- Railway 只运行一个 Nginx 静态服务，不运行 Node 服务、数据库、定时任务、WebSocket、保活探针或服务端 R2 代理。
- `railway.json` 启用 `sleepApplication: true`，单副本，CPU 上限 0.5、内存上限 128 MiB。部署后无流量时可自动休眠；下一次访问会唤醒，可能有短暂冷启动。平台套餐基础费用不由休眠设置取消。
- JS/CSS/HTML/JSON 在镜像构建时预压缩；模型按内容哈希命名，缓存一年。浏览器通过 Cloudflare 只读缓存入口请求 R2 模型，不通过 Railway 中转。
- 首页直接启动第三人称全屏 3D；建筑和主角优先，桌面街道资产三路并行加载并显示简短进度。加载失败可重试，不回退到插画。页面隐藏时暂停渲染与时间轴。
- `/healthz` 仅用于部署就绪检查，不创建外部定时探活。不要添加持续请求站点的 uptime 保活工具。
- Railway 容器无需任何 R2 凭证；上传只在可信本机通过 Cloudflare Wrangler OAuth 进行。

## 模型更新

生产 GLB 包含 Draco 几何与嵌入 WebP 贴图，共约 166.3 MiB，四幅远景画作另计约 5.3 MiB。建筑约 50 万面，复杂道具约 35 万面，普通道具约 18 万面；建筑与复杂道具采用 2K 贴图；新主角采用 60 万面、4K 贴图，经脸、手、靴子同姿态近景对比和表面偏差检查，完整 200 万面 / 8K 版本保留在本机。按近景质量判断，不再套用 8 千面 / 512 像素的统一减面模板。

模型几何和贴图修改使用 Blender MCP。Hi3D 原始模型保留在本机 `product-city` 文件夹；本轮高精度模型、逐件预览、处理记录和可编辑 `product-city-quality.blend` 保存在同级 `quality-work` 文件夹，未提交到公开仓库。

`reference/source-models.json` 是逻辑清单；`dist/assets/models/manifest.json` 包含本次发布绑定的 URL、SHA-256 和字节数。新增版本使用新的哈希路径，不覆盖旧资源。

```sh
npm run assets:prepare -- --source /path/to/optimized/models --base https://mycity-assets.lafreze-city.workers.dev/mycity
R2_BUCKET_NAME=mycity-assets npm run assets:upload
VERIFY_ORIGIN=https://mycity.up.railway.app npm run assets:verify
npm run check
```

上传脚本仅允许 `mycity/models/` 和 `mycity/landscapes/` 前缀，不会清理现有 R2 对象。完成验证后再提交更新的 manifest 和部署。公开资源由 `cloudflare/assets-worker.mjs` 提供，R2 桶保持私有，`r2.dev` 不启用。Worker 只开放带哈希的模型和画作路径，支持 GET/HEAD、Range、ETag、边缘缓存和指定来源 CORS；没有目录列表或上传接口。`config/r2-cors.json` 保留对应桶端读取策略，实际公开入口的允许来源由 Worker 管理。

发布资源入口：`npx -y wrangler@4.158.0 deploy --config cloudflare/wrangler.jsonc`。Worker 无定时触发器，只有资源请求时执行。

## 编辑作品

编辑 `dist/products.js`：名称、介绍、分类、上线日期、更新记录、状态、真实 `url`、`demo` 和联系邮箱。当前仍是示例产品；URL 为空时显示“链接待接入”。未接入真实 GitHub 产品活动。

首页默认为第三人称漫游，只有简短操作提示和探索进度。右上角“全景”切回原有年份、视角和作品浏览；建筑名牌只在全景悬停或选中时显示。

`dist/props.js` 控制街道物件与居民摆放；`dist/world.js` 定义河道、船吃水和沿 X 方向的水流。居民有各自的待机、工作与交谈动作；自行车、座椅、托盘等支撑物保持稳定，主角使用真正的骨骼动画行走。旧城区复用游戏厅模型；状态按时间轴变化。支持建筑详情、城市成长、日夜切换、旋转缩放、河岸 / 俯瞰视角、顺流漂船和手机操作。

`reference/model-quality.json` 记录实际导出的几何、法线、贴图、哈希和桥下净空；`npm test` 检查落水、穿墙、道具穿插、桥头、车辆朝向、船首方向与 20 分钟船轨迹。浏览器隐藏时暂停动画，静态阴影只在模型加载或年份改变时更新。

## 第三人称漫游

- WASD / 方向键行走，Shift 快走；拖动看周围，滚轮拉近或拉远。手机左下摇杆行走，右下按住快走，拖动场景改变视角。
- 靠近店铺或景点后按 E / 点击提示互动。8 处足迹仅保存在本机浏览器，可逛后街花园、旧城区、河畔咖啡与五类作品位置。
- 主角是新生成的青绿色外套、背包旅行创作者，通过 Blender MCP 绑定 20 根骨骼，包含待机、自然摆臂行走和快走动画。步频按实际位移与模型步幅校准，停止后过渡回待机。原始模型、骨骼文件和编辑场景保留在本机 `character-work`，只将成品 GLB 上传 R2。
- 角色沿障碍滑动、阻止穿墙和踏入河水；桥上高度来自实际模型测量，两端新增 7 级石阶。跟随镜头会避开建筑与树冠，作品弹窗打开时暂停输入。
- `dist/navigation.json` 是轻量碰撞数据，不对高密度模型逐帧做射线检测。道具加载后才启用相应碰撞；桥未加载时不能进入河道。更改模型尺寸、摆放或桥面后运行 `npm run navigation:build`，测试会检查数据是否过期及 8 处探索点是否互通。
- 角色动画属于动态层；停下时复用原精度街区缓存。切到后台后暂停渲染与人物输入。

## 街区居民与远景

- 9 位邻居：信使、工坊创作者、读者、咖啡师、花匠、骑行者、建造者、小机器人和小提琴手。原有 Hi3D 模型通过 Blender MCP 加入 4 秒 Idle / 3 秒 Talk，保留原模型面数、贴图、比例及固定支撑点。骨骼文件和回读验证保存在本机 `npc-work`。
- 靠近按 E，手机点击交流提示；全景模式也可点击人物。每位居民有两个简短话题、首次/再次见面和夜间招呼，部分对话可进入对应作品。镜头转向双方，关闭后恢复漫游。对白在 `dist/residents.js` 编辑，纯本地运行；邻里进度只存浏览器，没有聊天服务或新增服务器调用。
- 四幅同色调村庄、丘陵、果园、河谷画作覆盖四周，边缘交叠，河流和河岸向远景延伸；色调随夜景改变。每幅原尺寸 1376×768，原图保留在本机，生产版存 R2。生成记录见 `reference/landscape-generation.json`。
- 仅更新视野内的居民动作，远处 20 Hz、近处逐帧更新；离屏暂停并剔除，重新进入视野恢复。骨骼动作不触发静态街区重新绘制。
- 自动检查证明 9 位邻居及 8 处足迹均可步行抵达；已移开阻塞河畔通路的花盆并调整咖啡车。测试覆盖对话动作切换、近处人物可见、离屏暂停和资源释放。

## 手机与低内存设备

手机、iOS/iPadOS 和报告内存不超过 4 GiB 的设备自动启用轻量模式；`?quality=low` / `?quality=high` 可强制选择。轻量模式将像素比限制为 1，关闭多重采样、阴影贴图和静态 HDR 缓存；建筑与主角贴图上限为 1024，道具为 512，模型串行加载。保留五栋建筑、主角、桥、船等 16 种街道资产及 3 位居民，其他道具不下载。桌面默认保持原画质、完整街区和静态缓存。

WebGL 绘图中断时显示中文提示，可用轻量模式重试；卸载与失败重试会释放模型和贴图资源。`?debug=1` 提供只在本机读取的 `window.__mycityDebug`。诊断、逐资产内存估算、复现脚本和浏览器前后对比见 [docs/mobile-memory.md](docs/mobile-memory.md)。Chromium 手机模拟实测 JS 堆约 546 → 280 MiB，场景贴图估算约 1155 → 121 MiB；不代表实体手机帧率或内存上限验证。轻量模式省去静态缓存，会增加静止时的三角面提交量。

## 渲染性能

桌面高画质下，镜头停止时缓存原精度街区的 HDR 颜色和深度，只重绘水面、船、主角、可见居民、探索标记和夜间萤火；移动镜头时直接渲染完整场景。修改年份、日夜、视口或加载新模型都会使缓存失效。保留原 GLB、贴图、像素比例和多重采样抗锯齿；不支持 HDR 渲染目标的设备使用完整场景渲染。深度缓存保证船仍被河岸和桥正确遮挡。

点击/悬停使用不可见定位框，避免每次指针事件遍历数百万个三角面；拖动期间跳过悬停检测。白天关闭零亮度点光源，静止模型复用局部变换，加载和生长动画中的阴影更新合并处理。新增回归检查覆盖缓存重用、运动时完整渲染、深度、失效、缩放、资源释放和兼容回退。

2026-11-10 本机浏览器对比（1280×720 视口、像素比例 2，全部 40 种道具载入、默认日景）：

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 镜头静止时帧率 | 约 16 FPS | 约 60 FPS |
| 稳态每帧提交三角面 | 26,486,504 | 180,002 |
| 单次指针定位 | 约 20–40 ms | 约 0.1 ms |

新增漫游主角后，上述桌面环境日景静止约 60 FPS，稳态约 78 万三角面。加入居民与远景后，本机 1280×720、像素比例 1 的浏览器中，街道及交谈静止视角约 60 FPS；动态提交约 200 万三角面，随可见居民数量改变。390×844 布局已验证对话和人物可见，未作实体手机性能基准。

连续旋转仍提交完整场景，本机约 35 FPS；夜景河岸静止视角约 60 FPS。结果与设备、视角和加载阶段有关，不代表所有设备都达到这些数值。`?perf=1` 显示只在本机计算的诊断读数，不发送任何统计；正常入口不显示诊断文字。
